# Ghost Guide — architecture & engineering contracts

This is the single source of truth for how the codebase is organized. Read it
before changing code.

### Why `cacheComponents` is off
Many pages read per-user, RLS-scoped data at request time. The classic dynamic
model is simpler and avoids stale per-user data. Pages opt into caching
explicitly.

### Next.js 16 specifics you must follow
- `params` and `searchParams` are **Promises**: `const { id } = await params`.
- Use the generated global helpers `PageProps<"/admin/customers/[id]">`, `LayoutProps<…>`,
  `RouteContext<"/api/x/[id]">`. They are generated by `npx next typegen`
  (run by `npm run typecheck`). After adding a route, run `npx next typegen`.
- Middleware is now `src/proxy.ts` (`export function proxy`). It only refreshes
  Supabase sessions; **authorization happens in pages/actions/handlers**.
- `next lint` is gone; use `npx eslint .`.
- Server Actions: `"use server"` files; always validate input with zod and
  re-check auth inside the action.

## Database access rules

```ts
import { withUser, withAnon, withSystem } from "@/server/db";
await withUser(user, (tx) => tx`select … from public.profiles`);           // RLS applies
await withAnon((tx) => tx`select … from public.app_settings`);        // public reads
await withSystem((tx) => …);   // trusted code ONLY, bypasses RLS — authorize first!
```

- Rows come back **camelCase** (`user_id` → `userId`). JSON column contents
  are returned as stored — use camelCase keys inside JSON.
- **JSONB params:** `${tx.json(obj as JsonValue)}`. Never `JSON.stringify(...)::jsonb`
  (postgres.js v4 stores a JSON *string*).
- Arrays: `${ids}::uuid[]`, `${tags}::text[]`. Dates: always `timestamptz`; cast
  ambiguous params (`${d}::timestamptz`, `${s}::date`).
- `numeric`/`bigint` come back as JS numbers (custom parsers in db.ts).
- Lifecycle tables (audit, jobs, integration events) are **not writable by API
  roles**; write them in `withSystem` inside a use-case that has already
  authorized the actor.
- Customers can write their own profiles (limited columns).
- Catalog, provenance and `osm` tables are read-only for API roles: anon and
  authenticated may only SELECT published hikes and the rows that belong to them.
  Ingestion and the admin data-review page write through `withSystem`.
- Licence gate: content tables carry `license_code` plus `license_allowed`
  (always true) with a composite foreign key to `licenses (code, allowed)`, so
  rows under NC, ND, proprietary or unknown licences are rejected by the
  database. Photos have a second, stricter gate on `licenses.photo_ok`.
- OSM-derived values (geometry, points, length, elevation) live only in schema
  `osm`; hike pages read `public.hike_public`, which labels each value with its
  source and licence.
- Row locks: `select … for update` inside `withSystem` for state transitions.
- Return 404 (not 403) when a customer asks for a resource they don't own.

### Migrations
- Migrations start at `20261115000000_baseline.sql`. Add new ones with a later
  timestamp; never edit an applied migration.
  Every new table: enable RLS, add policies, and set grants explicitly
  (default privileges for API roles are revoked).
- The baseline is written with guarded statements (IF NOT EXISTS, guarded
  ALTERs, grants reset explicitly) so it also applies on the hosted database
  after `scripts/db/archive-v0-hosted.sql`; keep later changes to baseline
  tables guarded the same way until go-live.
- Apply locally: `npm run db:migrate` (or `npm run db:reset` to rebuild + seed).

## Auth & authorization

```ts
import { getCurrentUser, requireUser, requirePermission, getApiUser, jsonError } from "@/server/auth";
import { can } from "@/server/auth/rbac";
const user = await requireUser("/account");             // pages/actions; redirects to /login
const staff = await requirePermission("jobs.manage");  // admin pages/actions; redirects to /forbidden
const apiUser = await getApiUser(); if (!apiUser) return jsonError(401, "Sign in required");
```
`SessionUser = { id, email, roles: StaffRole[], isStaff }`. Roles: admin, operator,
content_editor, support (the database enum still lists `safety`; the app no longer
grants or honours it). Permission matrix: `src/server/auth/rbac.ts`.

**Testability rule:** use-case functions take an explicit `user: SessionUser`
argument and never read cookies themselves. Pages/actions/handlers resolve the
user, then call the use-case. Integration tests call use-cases directly.

## Jobs (durable background work)

```ts
import { enqueueJob, cancelQueuedJobs } from "@/server/jobs/queue";
await enqueueJob(tx, kind, payload, { dedupKey: `${area}:${entity}:${id}` }); // tx = the state change's transaction (or null)
```
- Enqueue in the **same transaction** as the state change (outbox pattern).
- Dedup keys make enqueue idempotent. Conventions: `<area>:<entity>:<id>[:<step>]`,
  `periodic:<kind>:<bucket>`. `cancelQueuedJobs(tx, prefix)` cancels queued jobs by key prefix.
- Handlers live in `src/server/jobs/handlers/<slice>.ts` and must be idempotent:
  re-load current state, compare versions, and return `{ outcome: "noop" }` when obsolete.
- Throwing = retry with exponential backoff; after `maxAttempts` the job is `dead`
  and appears in the admin retry queue.
- Periodic kinds (enqueued by every cron tick): `ops.purge_rate_limits` (daily).
- Run locally: `npm run jobs:run` (once) or `npm run jobs:run -- --watch`.

## Cross-cutting helpers
- `recordAudit(tx, actor, action, entityType, entityId, metadata)` — every sensitive staff action.
- `checkRateLimit(key, limit, windowSec)` — auth and public APIs.
- `isEnabled(key)` — feature flags (`src/server/flags.ts`; none are defined today).
- `log.info/warn/error(event, data)` — redacts secrets, contact details, coordinates.
- `assertSimulationAllowed("payments")` — every demo adapter calls this; throws in live mode.

## Honesty & safety rules (product requirements — non-negotiable)
- Label every simulated integration and demo datum (`<SimulatedBadge />`, "Demonstration").
- Ghost Guide is not an emergency service: never claim monitoring, tracking or rescue.
- Permits and bookings with agencies: official links only — no queue, CAPTCHA or booking bots.

## UI conventions
- Use `src/components/ui` primitives; tokens: `forest-*`, `sand-*`, `canvas`, `surface`, `ink`, `muted`,
  `amber-ink/bg`, `red-ink/bg`, `blue-ink/bg`.
- Touch targets ≥ 44px (`min-h-11`); labels on every input; `aria-live` for status changes;
  respect `prefers-reduced-motion`; no information conveyed by color alone.
- Mobile-first; test at 375px width.

## Shared modules
- `src/lib/format.ts` (money, dates, ages) and `src/components/ui` are shared by every area.
- `src/integrations/payments` (Stripe Checkout + simulated adapter) stands alone until the
  Phase 6 order checkout uses it.

## Semantics worth knowing
- **Job-runner heartbeat**: every runner invocation writes `app_settings.job_runner_heartbeat`;
  `getRunnerHealth()` (`src/server/jobs/health.ts`) reports staleness (> 5 min) to `/status` and the
  admin overview.
- **Service worker**: none. `public/sw.js` is a kill switch for browsers that installed the old offline
  worker: on install/activate it deletes every `gg-*` cache, unregisters itself and reloads open tabs. The
  app never registers a worker.

## Testing
- `npm run test:unit` — pure domain logic (`tests/unit/<slice>/…`).
- `npm run test:integration` — against `ghostguide_test` (recreated + seeded per run).
  Helpers: `tests/helpers/db.ts` (`demoUser`, `createCustomer`).
- `npm run test:e2e` — Playwright against a running server.
- `npm run verify` — typecheck, lint, tests, production build.
